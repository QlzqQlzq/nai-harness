# 配置说明

`CONFIG_FIELDS.md` 列出全部字段、用途和约束；同目录的 `config.reference.toml` 集中展示高级失败策略、每把 key 的独立覆盖、补购和命令别名等完整写法。省略的字段使用内置默认值；示例中的域名和环境变量需替换为自己的配置。

`keys = [{...}, {...}]` 每项代表一把 key；反复出现的 `[[drawing.sfw.endpoints]]` 每段代表一个不同 URL 的服务。配置参考仅在第一个出图服务完整展示通用字段，其他服务或 key 可按需采用相同字段；`auto_buy` 用于出图服务。

## 文件与生效

WebUI 优先入口及六类设置说明见 `CONFIG_WEBUI.md`。常用服务、URL、模型和多把 key 使用中文分类表单；任意映射表和逐 key 高级失败规则仍保留原文配置，未显示的已配置值不会被普通表单编辑清空。

MaiBot 首次加载时根据模型生成 `config.toml`。可通过宿主配置界面编辑；复杂嵌套服务列表也可直接编辑 TOML。修改后重载插件，重载会取消正在处理的任务并重建客户端。命令别名与自然工具注册的变更应执行完整插件重载。

实际设置写入宿主使用的 `config.toml`。通过 WebUI 保存后重载插件，`config.reference.toml` 供查阅写法。

`plugin.dry_run = true` 是解析测试模式：返回最终请求参数，不调用出图接口；解析模型、搜索和 tag API 仍可能联网。正常使用保持 `false`。

## 服务池位置

| 服务 | SFW 配置路径 | NSFW 配置路径 |
| --- | --- | --- |
| 出图 | `drawing.sfw` | `drawing.nsfw` |
| 独立文字解析 | `parser.services.sfw` | `parser.services.nsfw` |
| 反推 | `reverse.services.sfw` | `reverse.services.nsfw` |

搜索使用 `search.services`，正文抓取使用 `search.fetch_services`，tag API 使用 `search.tag_api_*`。这些服务不继承出图 key。所有 URL 都是完整端点，插件不自动追加 `/v1` 或接口路径。

链路由当前会话的 NSFW 设置选择，不使用自动内容分类器。开启 NSFW 的会话中，普通内容也走 NSFW 服务池。默认 `cross_fallback = "never"`，缺少该链服务时明确报未配置。跨链需显式配置方向；内容词表只是可配置的字面检查，不是完整图像审查。

每个池可无限追加 `endpoints`，每个服务可无限追加 `keys`。示例给出两套原生端点和一套 OpenAI 图片备用端点，可自行增删。`models` 为空表示不限模型；非空时按内部模型名过滤，`model_map` 负责转换为上游模型名。

## 顺序、轮询与每把 key

`pool.strategy` 控制服务选择，`endpoint.key_strategy` 控制服务内 key，均只接受 `ordered` 或 `round_robin`。顺序模式从第一可用项开始；轮询每次请求换起点。轮询游标重启后归零，冷却/停用状态默认持久化。

每把 key 的 `name` 是日志标识，`note` 仅作人工备注；这两项不拼进密钥。`env` 非空时只读取指定环境变量，不再回退到 `secret`。环境变量缺失会跳过该 key。匿名服务需开启 `anonymous`，并保留一项具名 key。

每 key 的重试、超时及各类错误规则优先于 `endpoint.defaults`。未设置或 JSON `null` 继承，TOML 中省略。嵌套错误规则也逐字段继承，`false` 与 `0` 明确覆盖，不被当成空值。

错误分类包括额度耗尽、认证失效、限流、超时、服务器错误、无效响应和其他请求错误。策略可选择仅本次跳过、冷却、停用至手动恢复、终止请求。重试须同时满足错误规则 `retry = true` 和重试次数未耗尽。总尝试次数、总时限优先于所有局部重试。

未填写 `defaults` 时，每个服务独立采用以下默认策略，不需要在每个服务复制一遍：

| 错误字段 | 含义 | 默认处理 |
| --- | --- | --- |
| `quota` | 上游额度不足 | 此 key 冷却 300 秒 |
| `auth` | 认证失败 | 此 key 停用，管理员恢复 |
| `rate_limit` | 限流 | 此 key 冷却 30 秒 |
| `timeout` | 超时 | 此 key 冷却 10 秒 |
| `server` | 服务器或网络错误 | 此 key 冷却 10 秒，允许重试但默认 `retries = 0` |
| `invalid_response` | 无有效图片或格式错误 | 本次跳过此 key |
| `bad_request` | 其他请求错误 | 停止当前路由尝试 |

`skip` 表示仅本次跳过，`cooldown` 表示跳过至冷却结束，`disable` 表示停用至管理员恢复，`stop` 表示停止当前路由尝试。若启用了匹配此错误类型的模型降级，还会受模型降级规则和全局请求预算控制。

例如，常用写法中给一把 key 单独设置额度不足时冷却一分钟：

```toml
keys = [
    { name = "primary", secret = "填密钥", env = "", quota = { action = "cooldown", cooldown_seconds = 60 } },
    { name = "backup", secret = "填另一把密钥", env = "" },
]
```

这段应替换对应 `[[...endpoints]]` 下的 `keys`，不能在同一服务重复写两个 `keys =`。完整参考的 `[[...endpoints.keys]]` 是等价的展开写法，与内联列表二选一。服务级 `defaults` 应属于服务，不能写成某把 key 的子项。

`paid = true` 的服务仅在池内 `allow_paid = true` 时调用。模型降级需配置 `generation.fallback_models` 与错误类型，所有目标模型须在允许列表内，禁止循环。降级会重建请求，并按实际模型调整本地额度。

上游超时可能发生在服务器已生成但响应丢失之后。再次尝试可能再次消耗上游额度，插件无法仅靠超时判断服务端是否已完成；谨慎配置超时重试。消息发送失败只重试发送已有图片，不重新调用生成接口。

## 权限与覆盖优先级

- `permissions.admin_qq`：全局管理 QQ，可修改群模型/NSFW、恢复 key 与补购状态。
- `permissions.group_managers`：按群配置模型/NSFW 管理 QQ，不授予全局运维权限。
- `permissions.groups`：按群配置启用、允许功能、初始模型与 NSFW。
- `private_enabled`、`private_features`、`private_manage`：分别控制私聊使用、功能范围与个人模型/NSFW 修改权限。
- 黑名单与白名单限制同样作用于管理员，避免管理员误触禁止群的接口。

模型和 NSFW：已保存的会话设置 > 群初始配置 > 全局群聊/私聊默认。画风与 UC 按平台和用户保存，不公开共享。个人设置、单次参数不能绕过权限、像素、角色数和额度上限。

自然对话绘图会返回一次性确认指令，用户发送后，按确认者所在会话的权限与额度提交。

## tag、画风与词库

纯英文/tag 默认原样直出，不要求联网。混写与自然语言进入独立解析器，保留显式 tag、权重与角色关系。未知普通词不等于未知角色；角色身份歧义需选候选，已明确查不到的角色拒绝生成。工具故障与明确无结果区分处理。

本地词库用 `dictionary.enabled/path` 配置，支持原插件 SQLite 格式，只读打开；相对路径位于宿主提供的插件数据目录。缺库返回 unavailable，不把缺库误报成角色不存在。`dictionary.aliases` 是人工确认的映射；模糊匹配仅作候选。

`parser.skills_dir/skills` 允许只读指导文字；目录相对插件数据目录，skill 不执行脚本，不新增工具。最多 16 项，每个 SKILL.md 最多 12000 字节。工具、轮次与总时限各有上限。

画师串、画风与预设统一在 `styles`。默认画风用于没有明确风格的自然语言输入，显式风格优先；纯 tag 只有显式开启 `apply_to_direct` 才追加。关闭画风管理不会删除用户正文中明确指定的风格。

OpenAI 图片接口使用 `role_mode = "fold"` 时，会把角色提示词合并到主提示词，独立角色位置和负面块随之丢失。需要保留角色块时使用原生接口，或设为 `role_mode = "reject"` 阻止折叠提交。

## 反推与重画

反推支持 OpenAI 兼容视觉模型和 `json_tagger` HTTP 服务。后者请求为 `{"images":["base64..."],"threshold":0.35}`，响应为 `{"tags":["tag"]}` 或 `{"tags":{"tag":0.9}}`。将已部署的标注服务 URL 填入对应端点即可。

`reverse.quote_first` 决定引用/附件优先级。有引用且优先引用时，找不到引用图会报错，不悄悄改用附件。只读取当前会话中的目标消息，默认一张，可配置多图。

重画使用本插件保存的生成记录，默认只允许自己的记录；无引用时可选择本人本会话最近一次。原图参数、种子、模型继承分别可配。其他来源图片先执行反推，再用返回的 tag 绘图。宿主未返回发送消息 ID 时，使用无引用重画。

## 额度、补购与恢复

本地额度不代表上游余额。用户/群额度、模型单价、周期及特殊用户/群覆盖均可配置。生成失败退款；已生成但发送失败默认计费，可单独开启退款。预占记录持久化，异常退出后默认保留不确定费用，可配置退款恢复。重复退款无效。

例如 `user_limit = 100` 且对应模型 `model_costs = 1` 时，该用户每周期最多生成 100 张；模型消耗设置为 2 时最多 50 张，还需满足群额度。仅在 `quota.enabled = true` 时生效。`user_limits = { "qq:123456789" = 200 }` 覆盖一个用户的周期额度，`group_limits = { "qq:g:123456789" = 2000 }` 覆盖一个群。带冒号的键名必须加引号。

`crash_recovery = "retain"` 在重启后保留未结算任务预占的本地点数，`"refund"` 退还本地点数；它不表示向上游申请退款。额度计数、上游 key 的余额不足处理以及自动补购分别负责不同事情。

补购配置在每个出图服务的 `auto_buy`，默认关闭，仅实现 rinko 兼容账户协议。三个 URL、账号、密码/环境变量、最低余量、每次包数、每日包数、单次 Gems 上限、冷却和失败方向均可配置。只在该服务返回额度不足后尝试；账户请求和补购后再生图共用出图预算。

购买之前持久化每日计数与待确认状态。购买超时、响应无效等情况下不重复购买；管理员应核对上游记录后执行 `/nai 恢复补购 服务名`。该命令不清除每日计数与冷却。`/nai 恢复key 服务名 key名` 恢复 key 状态；省略筛选会恢复全部。

## 数据与运维

运行数据只存于宿主提供的插件数据目录。图片、历史、日志各有保留限制；图片可同时按数量和总容量清理。默认不记录提示词，不保存 PNG 参数元数据；开启后可能保存用户输入。状态包含 QQ 标识、历史与额度，不应公开。

完整备份应同时保留实际配置和插件数据目录。分享配置前，移除密钥、认证请求头、账号密码、QQ 列表，以及 URL、代理和自定义提示词中的私人信息。
